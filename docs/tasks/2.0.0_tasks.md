# 2.0.0 — Task Board

**Sources:** [06 — Architecture & Defect Audit](../reports/06-2-0-0-architecture-audit.md) · `sast/final-report.md` (Security Assessment, 14 SAST classes + 3 correctness audits)
**Date:** 2026-09-07
**Baseline:** commit `c36db01`, `flutter analyze` clean, 466/466 tests green.

## The one fact that shapes this whole board

**2.0.0 is merged locally and has never been pushed or published.** Nothing on this
board breaks a consumer, because there are no consumers yet. A signature change that
would be a 3.0.0 conversation after publishing is, today, a free edit. Every P0 and P1
item below should land **inside 2.0.0**, before the first `pub publish` — not as a
2.0.1 patch apologising for a release that should not have gone out.

That window closes the moment the package is published. Work top-down.

## Priority key

| Tier | Meaning |
|---|---|
| **P0** | Publish blocker. Do not run `pub publish` with any of these open. |
| **P1** | Contract hole. Land in 2.0.0 while it is still free. |
| **P2** | Real defect, ships badly but survivable. 2.0.0 if time allows, else 2.0.1. |
| **P3** | Hygiene, docs, polish. 2.0.1 / 2.1.0. |

Each task answers: **What · Where · Why · How · When · Who.**
"Who" names the area that owns the change, not a person.

## T-02 — Fix the gate off-by-one: a closed gate on an integer level never blocks

| | |
|---|---|
| **What** | Make `clampTravelThroughGates` closed on the destination side, and re-apply the barrier per step in `moveTo`. |
| **Where** | `lib/src/rendering/character/saga_map_gate.dart:49,60` · `lib/src/rendering/character/saga_character_controller.dart:121,133-142` |
| **Why** | Both branches use strict inequalities on both ends: `if (at > from && at < limit)`. A gate whose `pathPosition` equals the move's destination fails `at < limit` and is skipped, so the character lands **on** the closed gate; on the next move it fails `at > from` and is skipped again, so it walks straight through. Two moves, gate bypassed, and it never applies again. This is the **only** progression barrier the package claims to enforce itself, and it fails in exactly the configuration the README teaches (`README.md:740-760`, `gates: [SagaMapGate(pathPosition: 29, ...)]`). A fractional placement like `29.5` works, which is why the green suite never caught it. Knock-on: `onLevelReached` fires for levels behind a closed gate, so a host awarding chapter state or arrival bonuses grants content behind an unbought ticket. |
| **When** | P0 — a paywall that does nothing is not publishable. |
| **Who** | Rendering / character |

**How**
- [x] **T-02.01** — Failing test added in `saga_gate_test.dart` ("a gate on the destination blocks").
- [x] **T-02.02** — Failing test added ("a gate on the origin still blocks the next move").
- [x] **T-02.03** — `:49` forward branch → `if (at >= from && at <= limit)` (origin closed, as T-02.02 requires).
- [x] **T-02.04** — `:60` backward branch → `if (at < from && at >= limit)`.
- [x] **T-02.05** — Multi-gate test added ("the nearest of two closed gates wins").
- [x] **T-02.06** — Open-gate regression test added ("an open gate on the destination passes freely").

## T-03 — `stableHash` produces a different world on web above 2^32

| | |
|---|---|
| **What** | Make the high-bit fold web-safe, then pin it with golden vectors that actually exercise it, run on a browser platform. |
| **Where** | `lib/src/core/domain/saga_stable_hash.dart:44` · `test/saga_stable_hash_test.dart:14-50` · `dart_test.yaml` |
| **Why** | Line 44 is `hash = _fmix32(hash ^ ((value >> 32) & _mask32));` — the one non-multiplication in a file whose header claims every operation is web-safe. The rest of the file carefully splits multiplication into 16-bit halves to stay under 2^53; the single line that actually needs 64-bit shift semantics was left raw. Measured: `stableHash([2^32])` returns `1284044959` on the Dart VM and `851875910` under dart2js/Node. A seed from `DateTime.now().millisecondsSinceEpoch` is ~2^40.7 — the most common way an app mints one — so **the same seed generates a different map on web than on native**, and on web such seeds collapse to their low 32 bits, aliasing seeds ~49.7 days apart onto the same world. This breaks the package's central promise, "same seed, same world." The suite cannot see it: every golden vector is under 10,000 (`0`, `[42,7]`, `[1,2,3]`, `i<2000`), there is no `--platform chrome` run, no browser platform in `dart_test.yaml`, and no `.github/` — no CI at all. |
| **When** | P0 — a determinism library that is not deterministic across its supported platforms. |
| **Who** | Domain / hashing |

**How**
- [x] **T-03.01** — Reproduced and recorded in the test header comment (VM vs dart2js/Node values).
- [x] **T-03.02** — `saga_stable_hash.dart` now uses `(magnitude ~/ 0x100000000) & _mask32` instead of `value >> 32`.
- [x] **T-03.03** — Negative inputs handled with a sign salt; documented as supported.
- [x] **T-03.04** — Goldens added above 2^32 (2^32, 2^32+1, 2^40, epoch ms, 2^32-apart pair) using **integer literals** — shift literals (`1 << 32`) would themselves diverge under dart2js.
- [x] **T-03.05** — `platform-parity` tag added to `dart_test.yaml`; suite tagged `@Tags(['platform-parity'])`.
- [x] **T-03.06** — Verified via `dart run` (VM) and `dart compile js` + Node (dart2js): identical on both. (Flutter `--platform chrome` run is sandbox-blocked; CI will run it — see T-26.)
- [x] **T-03.07** — Grep of `lib/` finds the raw `>> 32`/`<< 32` pattern nowhere except the hash file itself; consumers (`saga_map_level_generator.dart:72`, `saga_seed_utils.dart:10`) only call `stableHash`/`stableUnitValue`.
- [x] **T-03.08** — Added a "Correctness — stableHash is now web-safe above 2^32" section to `CHANGELOG.md`.

**Done when:** the same seed yields the same world on `vm` and `chrome`, proved by goldens above 2^32 running on both.

# Coverage note

The security assessment scanned 14 SAST classes. **Ten are structurally absent** —
SQLi, GraphQL, SSRF, XSS, XXE, SSTI, JWT, file upload, path traversal, RCE, hardcoded
secrets, IDOR — because `saga_map` is a client-side library with no server, no
database, no network stack, no auth and no privilege model. That is a real result, not
an empty one, and it is why every finding on this board is business logic, correctness
or packaging. No task here is a "security fix" in the usual sense; T-02, T-11, T-12 and
T-14 are integrity issues that matter only to a host promoting this state to a server,
and they are scoped that way deliberately.
